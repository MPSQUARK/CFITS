# WCS projection reference

The WCS regression vectors in `Tools/CFITS.Tests/Compliance` are independent
reference values. They are evaluated with Astropy's WCS implementation, which
bundles WCSLIB, and are not generated by CFITS.

Authoritative sources:

- NASA/IAU WCS Paper II, Greisen & Calabretta, *Representations of celestial
  coordinates in FITS*, section 6:
  <https://www.aanda.org/articles/aa/pdf/2002/45/aah3859.pdf>
- WCSLIB projection implementation, `cextern/wcslib/C/prj.c`, as bundled by
  Astropy:
  <https://github.com/astropy/astropy/blob/main/cextern/wcslib/C/prj.c>
- Astropy WCS projection documentation:
  <https://docs.astropy.org/en/latest/wcs/projections.html>

## Equations and defaults

The FITS `PV2_m` cards use the zero-based polynomial index `m` for ZPN.
Angles in the projection equations below are in radians unless explicitly
identified as degrees.

- **AZP**: with `mu = PV2_1`, `gamma = PV2_2`, and
  `r = (mu + 1) cos(theta) / (mu + sin(theta) +
  cos(theta) cos(phi) tan(gamma))`, the native plane is
  `x = r sin(phi)` and `y = -r cos(phi) / cos(gamma)`. Defaults are
  `mu = 0` and `gamma = 0`.
- **PAR**: with `s = sin(theta / 3)`, `x = (1 - 4s²) phi` and
  `y = (180/pi) 3s`. PAR has no projection parameters.
- **CYP**: with `mu = PV2_1` and `lambda = PV2_2`,
  `x = lambda phi` and
  `y = (180/pi) (mu + lambda) sin(theta) /
  (mu + cos(theta))`. Defaults are `mu = 1` and `lambda = 1`.
- **ZPN**: `r = (180/pi) sum(PV2_m * theta^m)`, with the zenith distance
  `theta` expressed in radians during polynomial evaluation. The resulting
  radius `r` is in degrees. The default polynomial is `PV2_0 = 0`,
  `PV2_1 = 1`; higher coefficients default to zero.

The AZP, PAR, CYP, and ZPN test vectors intentionally cover both defaults and
non-default coefficients, including AZP `PV2_1 = 45`, `PV2_2 = 0.5` and the
zero-based ZPN `PV2_0`/`PV2_1` convention.

## Maintenance

Keep reference values as independently evaluated constants. Do not calculate
expected values by calling `FitsWorld`, by round-tripping through the same
implementation, or by embedding Python in the test assembly. When optimizing
projection code, preserve evaluation order and angle units unless the change
is accompanied by independently verified vectors and focused differential
tests. In particular, do not move degree/radian conversion across polynomial
evaluation or reorder terms merely for apparent throughput.

Update vectors only when the authoritative source, Astropy/WCSLIB version, or
an explicitly documented numerical convention changes. Reproduce the values
with the authoritative implementation, record the source and version in the
change description, and review every changed vector against the prior result.
